# V1.0 角色与权限矩阵

单门店。角色为会员 member、员工 employee、店长 manager、管理员 admin。店长的「全店」是数据范围。具体写权限按下表控制。账号可兼有会员与员工身份，服务端按当前选定身份和渠道逐请求授权，身份权限不自动合并。

- — 表示拒绝。待开放及确认后生效的权限在相应决策完成前，由服务端拒绝并审计敏感尝试。后台到达页面不代表可提交写操作。
- 员工访问客户明细、跟进和任务时实时检查归属。转移后原负责人失去该客户数据访问权，历史保留。店长和管理员可访问全店相关记录。
- 会员仅可查询本人数据和核销凭证，不能执行核销。核销主体应在职且用途授权，不能以本人会员身份或客户端提交的角色绕过。两类员工来源码与兑换凭证分别授权及校验。
- 默认手机号脱敏。员工来源码、核销凭证明文、密码和搜索 HMAC 不进入日志。数据导出与额外手机号明文权限待确认，当前基线关闭。
- 四角色权限目录只读。修改员工角色通过员工管理操作并审计，目标角色和操作权限须经评审。BUSINESS_TIMEZONE 为固定业务配置，后台只读。

## 2.5.5 服务端接入

已接入 R1 会员注册、R2 本人资料、积分余额及订单详情，以及 R6 客户详情。R8 任务范围已提供服务端校验，员工必须同时是任务受指派人和客户当前负责人。其余业务接口随各模块交付，权限判定以本表为准。

每次请求按服务端会话的账号、当前角色和渠道重新验证资格。微信登录仍只签发会员或待注册会话。已存在且符合资格的员工会话可由服务端识别。正式员工登录、微信绑定和切换身份仍待确认。

员工数据查询只采用当前归属。跟进、家访和任务写入接入时，应在同一事务锁定会员行并复核当前归属，再执行操作。任务变更还须在同一事务校验任务负责人和状态。店长与管理员无需按员工归属筛选，具体操作受对应权限组控制。

已接入的功能权限拒绝返回 `403`，其中待开放能力返回 `FEATURE_NOT_AVAILABLE`。具备功能权限时，越界对象与不存在的对象均返回 `404`。权限依赖审计被拒绝的写请求，只记录账号、当前角色、渠道、权限组、拒绝类型和 Request ID。

管理员的 R17 配置写入须按已批准键开放，当前无批准写入键。R18 只读。权限基线不创建对应的业务写入口。
