# V1.0 业务规则
## 已确认
- 单门店，仅服务阳光口腔；会员/员工共用一个微信原生小程序，管理后台独立 Web。
- 不接支付，不开发预约挂号及预约管理，不存储临床病历、诊断、影像、治疗方案。
- 会员通过微信登录，服务端以临时 code 换取 OpenID。注册填写姓名、生日、手机号。手机号仅用于联系，允许家庭成员共用，无需短信验证。
- 员工专属二维码由服务端签发 scene_token。新会员使用有效来源码可建立首次归属。无效或过期来源码不阻止注册，已有会员再次扫码不改绑。
- 首次来源员工永久保留；当前负责人通过归属历史维护。客户转移仅店长/管理员，记录前后负责人、操作人、时间、原因。
- 到店 not_visited/visited、消费 not_consumed/consumed、成交 not_dealt/dealt 三项独立。
- 跟进类型 phone、wechat、home_visit、store_visit、other；家访与到店回访统一记录。
- 系统生成复查/唤醒名单，员工手动联系；不自动发送营销消息。
- 积分和库存变动保留不可变流水。兑换扣积分、写积分流水、扣库存、写库存流水和建单在同一事务内完成，支持幂等。订单只有待核销和已核销两种状态，V1.0 不支持订单取消和退款，注册赠分暂不启用。
- 动态核销凭证由服务端针对已提交的待核销订单签发。一次核销在同一事务内消费凭证、更新订单和写审计，同一订单只允许一次成功核销。
- 不创建 stores 表，不在业务表增加 store_id，不做门店切换/跨门店隔离。

## 商品月限兑（已确认）

- 门诊业务时区由服务端配置 `BUSINESS_TIMEZONE` 指定，V1.0 默认且已确认值为 `Asia/Shanghai`（UTC+8）。自然月统一按该时区计算，服务器系统时区、数据库会话时区和会员手机时区均不参与计算。
- 每位会员对每件商品按自然月累计兑换数量。`per_user_monthly_limit = NULL` 表示不限量。以订单 `created_at`（`TIMESTAMPTZ`）确定月份，先按业务时区计算本月月初和下月月初，再分别转换成 UTC，按 `[month_start_utc, next_month_start_utc)` 查询。
- 对区间内已提交的 `pending`、`verified` 订单按 `SUM(quantity)` 计数。事务提交后占用订单创建月份的额度，回滚不占额，跨月核销不会改变订单归属。详见[兑换详细设计](exchange-detailed-design.md)。
