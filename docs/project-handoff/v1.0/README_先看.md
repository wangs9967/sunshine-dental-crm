## 这份资料包用于什么
本包用于启动 Codex 开发，包含原始开发清单、V1.0 范围边界、模块清单、验收建议、待确认决策和 Codex 首轮指令。

## 已明确的两条范围边界
1. **V1.0 不包含预约挂号及预约管理。** 不开发预约创建、预约排班、预约状态流转、预约列表或预约管理后台。
2. **本系统不存储临床口腔数据。** 不建立病历、诊断、治疗方案、影像、检查结果、处方等临床数据存储模块。客户联系和回访记录只能记录运营沟通信息，不得把它扩展成临床病历。

## 可以开始开发吗？
可以开始项目初始化、工程结构、UI 页面、路由、组件、静态/模拟数据和基础交互。
但在真实业务上线前，仍需确认技术栈、数据库、接口、安全规则、积分规则、商品库存和核销流程。不要把本包中的“待确认”内容自行当成最终业务规则。

## 建议使用顺序
1. 先让 Codex 阅读本包所有 Markdown 文件及 Figma。
2. 让 Codex 检查现有代码仓库；若仓库为空，再提出技术栈方案，不要未经确认就大规模生成。
3. 先搭建三端框架与页面路由。
4. 按页面验收清单实现 UI 和交互。
5. 再根据已确认的数据字典/API 规格接入真实后端。
