# 数据与 API 设计待确认

> 下列仅为开发讨论用的候选实体，不是已经确认的数据库结构。先确认业务规则，再生成正式 ER 图、数据字典和 API 契约。

现行设计已收敛为 [18 表数据库设计](../../database-schema.md)和 [API 契约](../../api-spec.md)。下列候选清单保留立项时的讨论口径。

## 候选业务实体
- Member：会员基础身份与联系方式
- Staff：员工账号、角色、在职状态
- CustomerAssignment：客户与员工归属关系及变更记录
- FollowupTask：运营回访任务
- FollowupRecord：运营联系记录（严格禁止临床内容）
- PointAccount：会员积分账户汇总
- PointLedger：积分变动流水
- MallProduct：积分商城商品
- RedemptionOrder：兑换订单
- RedemptionCredential：核销凭证（服务端生成、校验、失效）
- StoreConfig：门店基础信息
- Role/Permission：角色与权限
- AuditLog：关键操作日志

## 不得建立的临床数据实体
不要建立 MedicalRecord、Diagnosis、TreatmentPlan、DentalImage、Prescription、ClinicalVisit 等临床数据表或等价存储结构。

## 接口域建议（待确认）
- 认证与账号
- 会员资料
- 员工与客户归属
- 客户运营跟进
- 积分账户与积分流水
- 商品与库存
- 兑换订单
- 动态核销
- 后台配置
- 权限与审计

## 必须确认的接口行为
1. 积分及库存流水只可追加，兑换扣减与订单写入同一事务。
2. 动态核销凭证一次性消费，重复扫码及并发核销不得形成第二次成功，凭证时长与刷新策略待定。
3. V1.0 无订单撤销和退款流程。
4. 客户转移保留完整归属历史。
6. 会员手机号、身份信息的脱敏、访问控制、导出权限和日志策略。
7. 软删除、数据保留期限、备份和恢复策略。
