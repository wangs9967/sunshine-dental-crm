# 可直接复制给 Codex 的首轮指令

你是阳光口腔 V1.0 项目的工程负责人。请先阅读本资料包内全部 Markdown 文件，并打开 Figma 设计稿：

https://www.figma.com/design/vHq5a7gAf59V1lDiR94NdH

## 第一步：只做仓库审查和实施计划
1. 检查当前仓库目录、已有代码、package/依赖文件、README、Git 状态和运行命令。
2. 不要覆盖或删除已有代码。
3. 如果已有技术栈，优先沿用；如果没有，请先提出 1-2 套技术方案并说明取舍，不要擅自定栈。
4. 输出目录结构建议、三端路由表、页面清单、组件拆分、数据实体候选、API 清单和开发里程碑。
5. 明确列出所有阻塞决策，不要猜测业务规则。

## 必须遵守的 V1.0 范围
- 不开发预约挂号、预约管理、预约排班或预约状态流程。
- 本系统不存储临床口腔数据；不得建立病历、诊断、治疗方案、影像、检查结果、处方等临床数据模块。
- 客户跟进只用于运营沟通，不得变成临床记录。
- 注册赠送积分当前待确认/暂未启用，不得自行开启。
- 商品月限兑规则已确认，商品具体额度配置化。“每月限兑 1 份”为示例，现行规则见[兑换详细设计](../../exchange-detailed-design.md)。
- Figma 的二维码仅是视觉示意，不是可用核销码。生产核销必须由服务端生成并验证动态凭证。
- 不要把示例姓名、会员编号、积分、订单号、统计数字当作真实生产数据。

## 第二步：等待确认后再编码
先提交审查报告和实施计划，等待项目负责人确认技术栈、业务规则和数据模型后，再开始分阶段实现。
每个阶段都要运行测试、类型检查和构建，并汇报变更文件及未完成事项。
