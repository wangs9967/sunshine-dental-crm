# V1.0 范围确认

## 一、纳入 V1.0 的业务闭环
会员注册 → 会员身份与员工归属 → 客户运营跟进 → 积分累计/查询 → 积分商城兑换 → 门店核销 → 后台管理。

## 二、明确纳入的模块
### 会员端
- 会员注册/注册信息填写
- 会员首页与会员身份展示
- 积分余额及积分记录入口
- 积分商城、商品详情、兑换确认、兑换成功
- 我的兑换/兑换订单查看
- 个人资料、隐私与协议入口
- 门店联系/导航等门店服务入口（具体跳转待确认）

### 员工端
- 员工工作台
- 客户新增、客户列表、扫码登记
- 客户归属与客户转移
- 客户跟进任务
- 家访记录
- 跟进历史/联系记录
- 员工个人工作信息

### 管理后台
- 数据总览
- 会员管理
- 员工管理
- 客户跟进/客户运营
- 积分商城商品管理
- 兑换订单管理
- 客户回访提醒
- 系统设置
- 角色权限与关键操作日志

## 三、明确排除
- 预约挂号
- 预约管理
- 预约排班、号源、预约状态、预约取消/改期
- 临床口腔档案存储
- 病历、诊断、治疗计划、处置记录、口腔影像、检查结果、处方等临床数据存储
- 任何将运营回访记录转变为电子病历的设计
- 支付、兑换订单取消和退款

## 四、运营数据与临床数据的边界
允许的运营记录示例：联系时间、联系渠道、是否联系成功、客户意向标签、下次联系日期、员工备注（仅运营沟通内容）。
禁止的临床记录示例：牙位/牙周检查、诊断结论、治疗方案、治疗过程、影像、检验结果、处方和临床医嘱。
如确需查看临床资料，应由门诊既有合规临床系统承担；阳光口腔 V1.0 不复制或保存临床数据。

## 五、必须保持可配置/待确认的规则
- 注册是否赠送积分及赠送数值：当前设计标注“暂未启用/待确认”，不得擅自开启。
- 商品兑换限额：按每会员、每商品、每自然月计量的规则已确认。`per_user_monthly_limit` 随商品配置，`NULL` 表示不限量；“每月 1 份”为示例。业务自然月采用 `BUSINESS_TIMEZONE=Asia/Shanghai`，以订单 `created_at` 归属。详见[现行兑换设计](../../exchange-detailed-design.md)。
- 商品库存、积分价格、上架状态、兑换时间窗：由后台配置，具体字段与规则待确认。
- 兑换扣减随订单原子提交。积分获取、过期和人工调整细则待确认。
- 员工客户归属、转移权限和操作审批：待确认。
