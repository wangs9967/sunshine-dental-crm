# 2.6.4 客户跟进与回访管理手动验收

## 启动隔离环境

本地需安装 Docker Desktop、Python 3.12、uv、Node.js 和微信开发者工具。先启动 Docker Desktop。在项目根目录打开两个 PowerShell 窗口，分别执行：

```powershell
Set-Location backend
uv sync --locked --extra dev
$env:PYTHONPATH = (Get-Location).Path
uv run --locked --extra dev python tests/preview_followups.py "$env:LOCALAPPDATA/SunshineCRM/2.6.4-preview"
```

```powershell
Set-Location admin-web
npm ci
$env:ADMIN_API_PROXY_TARGET = "http://127.0.0.1:18164"
npm run dev -- --host 127.0.0.1 --port 15164 --strictPort
```

- 健康检查打开 [FastAPI /health](http://127.0.0.1:18164/health)，预期返回 `{"status":"ok"}`。
- 管理后台打开 [本地后台](http://127.0.0.1:15164/assignments)。隔离目录的 `credentials.local.json` 提供本次随机生成的管理员和店长密码。
- 微信开发者工具导入 `%LOCALAPPDATA%\SunshineCRM\2.6.4-preview\miniprogram`。沿用项目 AppID。开启本地调试的域名校验豁免。若提示找不到 TDesign，在副本安装依赖后点「工具 → 构建 npm」。
- 新建编译模式，启动页面选 `pages/staff/dashboard`，启动参数填 `staff=a` 或 `staff=b`。点击编译并冷启动。工作台应显示对应员工可访问的客户和任务。副本加载由真实 Session Service 签发的本地员工会话。本轮验收无需扫码，也无需使用真实微信凭据。
- 预置员工甲负责客户甲、乙，员工乙负责客户丙。每个客户各有两条回访任务和一条电话跟进。用「验收客户甲」等名称搜索。

## 验收流程

| 操作 | 通过标准 |
| --- | --- |
| 员工甲打开「回访」，将客户甲一条任务连续延期两次 | 每次显示新计划时间，只有一条原任务，状态为已延期。 |
| 完成该任务并填写结果，另选一条任务执行忽略 | 各自显示终态和最新时间，终态没有操作按钮。完成任务后没有新增跟进记录。 |
| 员工甲进客户乙详情，先录入电话跟进，再录入家访 | 保存后进入对应历史。普通跟进与家访在完整历史中按时间排列，家访页面只筛选家访。 |
| 管理员及店长分别进入「客户跟进」的 `/followups` 页面 | 能按会员、员工和北京时间日期组合筛选，能展开查看完整沟通内容，分页与筛选总数一致。 |
| 管理员及店长分别进入 `/tasks`，选择有负责人的客户并创建人工回访 | 当前负责人正确显示，提交后显示任务的会员、负责人、计划时间及待回访状态。 |
| 在后台「客户归属」把客户乙由员工甲转给员工乙。员工甲回到列表和回访页；若转移时刚好停在跟进表单，尝试提交 | 员工甲看不到客户乙及其任务，已经打开的表单提交显示客户不在负责范围。 |
| 用 `staff=b` 冷启动，查看客户乙详情和任务；管理人员在后台忽略该客户遗留的待回访任务，再为新负责人创建任务 | 员工乙可查看客户乙跟进历史，旧任务仍属员工甲且不出现在乙的列表，新任务才出现在乙的列表。 |
| 关闭 FastAPI 后刷新已加载页面或提交操作 | 显示请求异常。启动新一轮验收后重新进入；提交异常时可先查看历史或任务状态确认服务端结果。 |

## 清理与重启

在启动窗口按 Ctrl+C 停止 FastAPI 与 Vite。测试容器由启动脚本自己清理。关闭小程序副本，清理本次验收目录里的临时凭据和副本。需要保留旧验收副本时，将启动命令的目标目录换成一个全新的路径，使用新目录生成的凭据重跑。
