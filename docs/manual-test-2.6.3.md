# 2.6.3 员工账号开通与微信绑定验收指南

## 准备

1. 使用隔离的 PostgreSQL、Redis 和 FastAPI，准备一名管理员、一名店长和至少一名测试会员。后端使用测试 AppID 对应的 AppSecret。启动方式见[本地开发说明](local-development.md)。
2. 在浏览器打开隔离后台登录页。在微信开发者工具导入指向同一隔离 API 的小程序测试副本，点击「编译」。
3. 真实扫码需要有权限的测试微信及相机。手机需能访问隔离 API，后端需通过测试 AppID 允许的 HTTPS 地址提供服务。127.0.0.1 仅供本机模拟器使用。请使用模拟会员资料。

## 开通与绑定

| 操作 | 预期结果与通过标准 |
|---|---|
| 管理员进入「员工管理」，点「开通员工」，输入未使用的工号及姓名。 | 自动进入详情，显示在职、微信未绑定。使用同一工号再提交，提示工号已存在。 |
| 在详情点「生成绑定二维码」，核对失效时间；再点「重新生成绑定二维码」。 | 新码有效期 10 分钟。旧码、过期码及已使用的码不能绑定。 |
| 员工本人在现场打开小程序，点「扫描员工绑定二维码」，扫描管理员出示的新码。 | 提示已绑定。后台详情自动更新为微信已绑定，二维码收起。 |
| 为另一个员工签发新码，用已绑定的同一微信扫描。 | 提示微信已关联其他身份，第二个档案仍未绑定。 |
| 用店长账号登录，在「员工管理」打开列表和详情。 | 可以查看姓名、工号、在职和绑定状态。没有开通、签发、停用及重新启用按钮。 |

## 员工登录、恢复与退出

| 操作 | 预期结果与通过标准 |
|---|---|
| 在小程序点「员工微信登录」。 | 已绑定且在职的员工进入工作台，未绑定微信不能进入。 |
| 打开「我的」与「客户」。如需客户数据，在后台「客户归属」把测试会员分配给该员工。 | 「我的」显示本人姓名、工号及状态；客户列表只显示本人当前负责的客户。 |
| 保持登录，关闭并重新打开小程序，或在模拟器重新编译。 | 重新换码后恢复员工工作台。 |
| 执行「退出登录」，再关闭并打开小程序。 | 返回登录入口，冷启动也停留在入口。 |

## 停用、重新启用与会员回归

1. 用已有会员身份的测试微信绑定员工。绑定前后用会员入口登录，核对会员编号、资料和积分。通过标准是原会员编号、资料及积分不变，原有订单仍归本人。
2. 员工保持登录，管理员在员工详情点「停用员工」并确认。员工再次打开客户或个人资料应回到登录入口，重新员工登录仍被拒绝。同一个微信通过会员入口仍可使用会员功能。
3. 管理员点「重新启用」并确认。员工重新微信登录后才能进入工作台和读取客户。旧 Access Token 和 Refresh Token 永久失效由后端集成测试验证。

## 常见情况

- 提示绑定邀请无效时，由管理员重新生成二维码，再由对应员工本人现场扫描。
- 开发者工具若要求登录、扫码授权或信任项目，由项目负责人在工具内确认。编译通过只表示项目可在模拟器运行，真机扫码需单独验收。
- 登录或读取失败时，核对小程序 AppID 与后端一致，以及小程序和管理后台是否指向同一个隔离 API。
